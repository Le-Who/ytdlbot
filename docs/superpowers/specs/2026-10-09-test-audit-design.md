# Аудит кода и тестового покрытия — 9 октября 2026

## Цель и критерии результата

Изучить всю отслеживаемую кодовую базу проекта, сопоставить модули с существующими проверками, оценить релевантность и объективность тестов, построить схему необходимого покрытия и независимо перепроверить результат. Дополнение пользователя: найденные проблемы, требующие исправления перед покрытием, исправлять.

Результат: воспроизводимые измерения, карта каждого исходного файла, исправления подтверждённых ошибок с регрессионными тестами, замена явно ложных проверок поведения, план оставшихся полезных тестов и независимое ревью. Процент исполнения строк не считается доказательством корректности.

## Ограничения

- Python 3.12 и закреплённые requirements.txt / requirements-ci.txt.
- Детерминированные проверки без обращений к сторонним провайдерам и production.
- Сохранять пользовательские файлы и текущую ветку; не публиковать, не деплоить и не коммитить автоматически.
- Не перестраивать архитектуру; исправлять доказанные причины, сохраняя публичные интерфейсы.
- Для новых исправлений: наблюдаемый RED до реализации, GREEN после, проверки утечек и побочных эффектов.
- Параллельные аудиторы работают по независимым областям; изменения кода интегрируются задачами, с независимым ревью.
- Reasoning сабагентов не ниже high; xhigh для конкурентности и общего ревью.
- Сетевые диагностические скрипты и live acceptance не считать доказательством production без реального контролируемого прогона.
