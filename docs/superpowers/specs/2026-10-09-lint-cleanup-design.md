# Очистка Ruff/mypy и согласование версий

Пользователь разрешил выполнить рекомендованную очистку линтеров и обновить их версии. Работа продолжает исправленный после полного тестового аудита checkout; предыдущие изменения и исходные пользовательские untracked файлы сохраняются.

## Результат

- Ruff и mypy закреплены на актуальных стабильных версиях, проверенных через официальные PyPI metadata: Ruff 0.16.10, mypy 2.4.0 на 9 октября 2026. Runner pre-commit закреплён при необходимости для воспроизводимой проверки hooks.
- Одна конфигурация и область Python-проверок работают локально, в hooks и CI. Mypy проверяет app с установленными project dependencies; Ruff проверяет app/tests/scripts/tools и поддерживаемые root Python diagnostics. Runtime dependencies не обновляются в рамках задачи.
- Mypy app проходит без ошибок; Ruff check и format --check проходят. Семантически важные исключения правил имеют локальную точную причину; массовое отключение правил, type: ignore ради результата и unsafe autofix не допускаются.
- Обработка best-effort UI/logging/cleanup сохраняет свои границы. Ошибки durable storage, receipt, ownership и cancellation не превращаются в молчаливый успех.
- Изменения поведения требуют воспроизводителя/регрессионного теста. Механические imports/format/annotations проверяются существующими тестами без дублирующих tests.
- Финальная проверка включает полный офлайн-suite, реальные запускаемые lint/type commands и независимое ревью. Live provider/Telegram/browser/Docker действия не выполняются; clipboard остаётся изолирован.

## Границы и критерии ревью

Receipt truthiness остаётся совместимым с существующими вызывающими функциями; переменные bool/receipt/error не смешивают разные контракты. Type narrowing следует фактическому API, а не cast/Any, скрывающему ошибку. Async file/process операции сохраняют ownership и cancellation fences; маленькое синтетическое test I/O не переписывается в сложный runtime без причины. Исключения на extensible внешних границах допустимы с точным rationale и наблюдаемым исходом.

Работа идёт в существующей codex/update-runtime-documentation ветке без commits/push/deploy. Согласованный ранее reasoning сабагентов >= high сохраняется; параллельная реализация разрешена только для непересекающихся файлов, полный прогон централизован.
