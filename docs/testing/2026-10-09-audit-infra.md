## Objectivity and test-suite design

- **Strong existing tests:** release script tests execute current shell with failures and assert restored filesystem/runtime fake state; collector uses actual production code and exact sanitized numeric outputs; evidence validator rejects mutated inputs instead of only accepting fixture. These are valuable and should stay.
- **Fake lock is not a deployment lifetime lease.** release fake_host flock at358 creates marker, optional sleeps, deletes marker before returning; a real flock holds descriptor through activation. test484 overlaps only the fake acquisition call. Add native Linux flock test which starts second deployment while first is blocked inside pull/health after acquisition. Existing test title overstates protected-phase exclusion.
- **Fake Docker bypasses payload semantics.** fake_host docker exec recognizes getWebhookInfo in command and exits based on flag, never executes embedded Python or validates actual JSON. Same for volume ownership check. Unit fakes are appropriate but must be paired with small embedded-program execution tests for wrong webhook/url/root/local JSON and permissions, or real ephemeral container job.
- **Test title broader than input:** release801 says SHA/image/project/compose, mutates only SHA. Parameterize each required manifest field plus duplicates/missing checksum/mismatched hash; assert no pull/activation.
- **Static substring gates can remain green with dead code.** release845,1043,1060,1099,1256 and adapter432,577,722 inspect strings. They usefully guard declared configuration but are not executable proof of cleanup, isolation, parser correctness or command ordering. Add an execution-level oracle for key invariants, retaining concise static config tests.
- **Nested acceptance reruns tests already in full suite:** test_media_release.py:771 spawns another pytest subprocess over21 nodes including slower deploy tests; .github/workflows/test.yml also repeats full release-script suite after full tests. deploy.yml says pytest invoked once but the nested aggregator invokes it again under the hood. Keep one dedicated acceptance job/command listing nodes; validate node existence cheaply in normal suite and run them once. Parent full-suite timing can quantify overhead.
- **Duplicated validator logic is tested instead of production finalizer.** test_media_release.py `_validate_evidence` deeply validates generated fixture independently; collector finalizer/_resume_state has less validation. Mutations that fail the test-only validator need also be sent to production collector/finalizer. Particularly redaction, unknown nested values, malformed resume and receipts.
- **Platform coverage:** only Python3.12/Linux CI, Windows process tree tests skipped there; local Windows release fake shell tests do not validate Linux kernel flock/process/symlink behavior. Separate Windows subprocess contracts and Linux fake/native infra contracts; don't infer cross-platform proof from one green platform.

Priority useful additions: (1) actual MetricsCollector exposition->embedded helper contract; (2) adapter receipts->collector full-delivery matrix; (3) strict resume/smoke redaction; (4) safe pure exporter filters/argv/cleanup/cancel; (5) native lock lifetime plus deployment rollback fault injection at every state commit; (6) direct legacy/helper function contracts under fake resource/HTTP/DB boundaries; (7) container Compose permissions/readiness/local-file upload smoke; (8) validate CI runs critical tests once and report live evidence separately.
